# 理解代码与介绍项目

## 五分钟介绍顺序

先说明目标：技术资料问答需要证据可追溯，而且要能定位“没搜到证据”和“拿到证据但生成错误”。然后解释数据流：上传→解析→稳定切块→BM25家族与Dense→RRF→可选重排→LLM→引用校验。用同一个问题展示英文来源、中文回答和Chunk原文，再展示40题草稿评测表及失败案例，最后讲本地常驻模型、SQLite和向量缓存的工程取舍。

明确个人贡献：本项目使用AI协作开发，自己需要能运行、读懂、修改和解释对应模块。不能把AI起草题目写成人工标注，也不能把小种子集成绩写成真实用户准确率。

## 常见追问

1. 为什么BM25和Dense一起用？BM25擅长词面/缩写匹配，Dense能跨语言和表达变化；各自有失败，比较同一标注集排名而非只看示例。
2. 为什么不是直接加score？BM25分数和余弦含义、尺度不同；RRF只用名次。相关的词级/字符/翻译通道先合成一张词法家族榜，减少重复投票。
3. 为什么还要重排？双塔Embedding事先独立压缩文档和问题，Cross-Encoder同时看query/passage，能精排但每个候选都要算一次，因此只对有限候选做。
4. 英文问题如何找中文？保留原文并补中文译文，两个查询都进词级/字符索引；Dense另一路直接使用原问题。回答语言独立设置。
5. 怎么保证引用？ID必须来自实际给模型的证据；返回source/page/字符区间/原文。这个校验只能保证来源存在，事实蕴含仍需人工审核。
6. 没答案怎么办？检索空时直接拒答；Dense总能找到近邻，因此生成模型还需判断证据是否足够，评测中单列无答案子集；不把余弦当置信概率。
7. 为什么查询加载很慢？新进程冷启动读取权重并初始化CUDA；常驻服务只加载一次。磁盘向量缓存用于重启/增量接入，不等于GPU模型常驻。
8. 什么是Agent？模型以JSON选择search/read_chunk或final，程序校验白名单/参数/已观察ID，最大步数避免循环。不是给模型任意shell权限。
9. 服务并发如何？当前单进程锁保护模型与索引，多个请求排队；适合个人本地原型。扩展需要任务队列、读写快照、持久向量索引与鉴权。
10. 为什么SQLite？无额外数据库服务，事务保证文档/块一同保存；内容hash使重复上传幂等；向量按内容和模型指纹缓存。适合小语料，不冒称分布式方案。

## 失败分类

解析失败：编码/扫描PDF/版面；切块失败：证据被割裂或上下文太长；检索失败：术语/翻译偏移/候选截断；重排失败：被截断或相关性模型不适配；生成失败：证据不充分/指令注入/无依据推断；引用失败：假ID或引用存在但不支持断言；服务失败：下载/显存/API超时/并发排队。每类分别记录，不用一个“回答不好”概括。
